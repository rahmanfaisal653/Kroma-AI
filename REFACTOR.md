# Universal Refactoring Skill

## Purpose

Improve the internal structure of an existing project without changing its intended behavior.

Goals:

- Improve readability.
- Improve maintainability.
- Reduce complexity.
- Eliminate duplication.
- Organize code and folders more clearly.
- Reduce technical debt.
- Keep the project consistent and easier to extend.

## Rules

- Understand the existing code before making changes.
- Preserve existing behavior unless explicitly instructed otherwise.
- Refactor only within the requested scope.
- Reuse existing code before creating new implementations.
- Do not create duplicate logic, files, folders, or responsibilities.
- Organize code and folders by clear responsibility.
- Use short, descriptive, and consistent names.
- Remove confirmed dead code and obsolete structures.
- Simplify code where possible without reducing readability.
- Avoid unnecessary abstractions, nesting, dependencies, and files.
- Keep changes small, incremental, and easy to review.
- Follow the project's existing architecture, conventions, and style.
- Verify that functionality remains unchanged after refactoring.

## Golden Rule

Refactor to make the project easier to understand, maintain, and extend—not simply different.
